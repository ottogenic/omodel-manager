# Contributing to omodel-manager

A small, private, single-maintainer project. The workflow below keeps history clean and
releases traceable without ceremony.

## Branching — GitHub Flow

- **`main` is always releasable.** Never commit directly to `main`.
- **Short-lived feature branches** off `main`, named by type:
  - `feat/<slug>` — a new capability (e.g. `feat/docker-context-remote`)
  - `fix/<slug>` — a bug fix (e.g. `fix/resolve-target-leading-slash`)
  - `chore/<slug>` / `docs/<slug>` / `refactor/<slug>` — everything else
- Keep a branch focused on one change. Rebase on `main` before merging.

## Commits — Conventional Commits

Format: `type(scope): summary` in the imperative mood.

```
feat(profiles): add glm-4.7-flash
fix(logs): exit cleanly on Ctrl-C instead of a traceback
docs(readme): document remote setup
chore(cli): add --version flag
```

Types: `feat`, `fix`, `docs`, `refactor`, `chore`, `test`. `scope` is optional
(e.g. `profiles`, `remote`, `setup`, `assets`, `cli`). Add a body when the "why" isn't obvious.

## Merging

- **Squash-merge** feature branches into `main` so `main` reads as one clean commit per
  change. Delete the branch after merging.
- The squash commit's subject should itself be a Conventional Commit.

## Releases — SemVer + tags

Version lives in `__version__` inside `omodel-manager`.

- `MAJOR` — a breaking change to CLI flags, config output, or `model_manager.json` shape.
- `MINOR` — a backward-compatible feature (new flag, new profile, new command).
- `PATCH` — a backward-compatible fix.

To cut a release: bump `__version__`, add a dated section to `CHANGELOG.md`, commit as
`chore(release): vX.Y.Z`, then tag:

```bash
git tag -a vX.Y.Z -m "vX.Y.Z"
```

## Before you open a PR / merge

1. `python3 -m py_compile omodel-manager` passes.
2. `python3 -m unittest` passes (fast, offline — no containers, no network).
3. `python3 omodel-manager list` and `launch <profile> --dry-run` produce sane output.
4. If you touched `model_manager.json`, you also updated `DEFAULT_CONFIG` in the script
   (they must stay identical — the test suite enforces this).
5. Docs updated (`README.md` for user-facing flags, `AGENTS.md` for architecture) and a
   `CHANGELOG.md` entry added under **Unreleased**.
6. No new third-party imports — stdlib only. Runtime identifiers (`otools.*` labels, the
   SSH key and token paths) unchanged (they're load-bearing for live deployments).

## Style

- Match the surrounding code: comment density, naming, and idioms already in
  `omodel-manager`.
- Keep it a single script with one companion JSON. Don't split into a package unless the
  tool genuinely outgrows one file.
- All Docker access goes through `docker()`; build argv lists, never `shell=True`.

## Secrets (never commit)

- HF token: `~/.config/otools/hf_token` (chmod 600) or `$HF_TOKEN`.
- SSH key: `~/.ssh/otools_model_manager_ed25519` (generated by `setup --fix`).
- `.gitignore` already excludes `assets/`, `.otools/`, `*.bak`, caches. `model_manager.json`
  **is** committed (curated profiles, no secrets).
