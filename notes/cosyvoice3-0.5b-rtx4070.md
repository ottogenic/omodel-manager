# CosyVoice 3 native RTX 4070 trial (experimental)

- Source: `FunAudioLLM/Fun-CosyVoice3-0.5B-2512` revision `29e01c4e8d000f4bcd70751be16fa94bf3d85a18`; CosyVoice code revision `074ca6dc9e80a2f424f1f74b48bdd7d3fea531cc`. The native runtime is used rather than the vLLM-Omni 0.28 adapter: that adapter does not pass its `instructions` request field into the CosyVoice 3 prompt.
- Device: local `rtx4070`, with `rtx4070-asr` left resident. The profile is recorded in `DEFAULT_CONFIG` with experimental status; the tested FP16 helper remains the default launch mode.
- Image: `otools-cosyvoice3:0.1.1`, built from `utils/card/Dockerfile.cosyvoice`; source pinned, native (no vLLM/TRT). Reference voice files mounted at `~/.local/share/otools/cosyvoice3/voices`, model at `~/.cache/otools/models/cosyvoice3-0.5b-2512` read-only.
- Browser UI: `utils/card/cosyvoice_ui.py`, initially container loopback `127.0.0.1:8005`, then moved to `127.0.0.1:8001` to reuse the existing tailnet-only HTTPS route after a new Tailscale Serve port was denied to the unprivileged user. Clone uses `inference_zero_shot` plus an exact reference transcript; instructed speech uses `inference_instruct2` plus reference audio. Both request `stream=True`. Saved references require explicit consent and live in a persistent directory. This is an experimental UI, not the stock upstream `webui.py` (whose instruct mode calls the earlier `inference_instruct`).
- Baseline before trial: Qwen3-TTS Omni on port 8004 READY; Qwen ASR on 8003 READY; RTX 4070 10,502 / 12,282 MiB in use. Qwen Omni was stopped via `omm stop rtx4070 -y`, container retained. Earlier Gradio rollback container on 8001 also remains stopped.
- Outstanding: audible tag effectiveness and full browser-turn timing remain to be qualified; the user listened to Hughgo in the app and preferred the FP16 voice.
- First image build failed at upstream `openai-whisper==20231117`: its isolated build imported `pkg_resources` from a newer setuptools where it was missing. Image build now installs `setuptools<81` and Whisper without build isolation, before the remaining pinned requirements. No candidate container was started by the failed build.
- First candidate startup attempted to download optional `wetext` normalization assets from ModelScope; one asset returned 403. Second image omits this optional frontend (native text/tokenizer path remains, but number/symbol normalization may be less polished).
- 2026-09-26 operational result: native 0.5B container READY on loopback 8001 with Qwen ASR still READY on 8003. Existing `tailscale serve status` maps `https://otto-home.tail1faf4a.ts.net:8001/` (tailnet-only) to that loopback port; HTTPS HEAD returned 200. Idle GPU use 8,340 / 12,282 MiB, 3,783 MiB free (compared with 10,502 / 12,282 MiB under ASR+Qwen TTS). This is idle VRAM, not peak concurrent synthesis.
- Smoke-tested through the Gradio API using upstream's `asset/zero_shot_prompt.wav` and the exact reference phrase from `example.py`. Clone completed with HLS stream (first streamed event about 3.69 s cold; 1.52 s warm). Clone text containing `[laughter]` and `<strong>…</strong>` completed (~1.93 s); instruction `Speak slowly and softly.` completed (~1.42 s warm). A streamed playlist returned 200 over the *HTTPS tailnet address*. API acceptance is not proof of audible tag effectiveness, naturalness, cloned identity or smooth browser playback; listen before qualifying. The UI's instruction path wraps plain text in the upstream `<|endofprompt|>` template; reference audio is passed by file path rather than a tensor.
- Saved-reference UI requires an explicitly checked consent box and transcript; persistence and playback of a user-provided saved voice have not yet been tested. No new user voice was saved during the smoke test.
- Tailscale Serve refused a new port without sudo authentication, so no Serve settings were changed. Reused the existing tailnet-only 8001 route instead; 8787 `otalk-app` route remains untouched. `omm` helper mounts the editable UI source read-only to the candidate container for testing; it remains part of the image too.
- 2026-09-26 app integration: user saved `Hugh.wav` + `Hugh.json` (transcript and consent true). Added native `GET /api/voices` and `POST /api/speech` to the CosyVoice UI server. Speech selects an existing consented reference by exact name, uses native `inference_zero_shot(..., stream=True)`, and yields signed 16-bit 24 kHz mono PCM to the Node proxy. A direct Hugh test returned first PCM ~3.74 s and 541,440 bytes in ~10.88 s; HTTPS through `otalk-app` returned first PCM ~3.92 s and 631,680 bytes in ~9.59 s. `/api/voices` on HTTPS 8787 lists `Hugh`; unknown voice and blank text return 400. Both app and ASR stayed READY. No browser microphone or audible playback test yet; no expression directives are injected into normal app replies.
- 2026-09-26 follow-up: user saved `Hughgo` separately. CosyVoice now uses upstream `add_zero_shot_spk` once per unchanged saved reference (WAV mtime/size + exact transcript) under the synthesis lock, and passes its speaker ID into `inference_zero_shot`. It prewarms all saved voices on startup (Hugh 1.221 s, Hughgo 0.245 s in restart logs); new voices prepare on first use; changed source files cause a new speaker ID and replace the old in-memory profile. It does not write `spk2info.pt` into the read-only model mount. `otalk-app` now prefers `Hughgo` when it appears in the voice list; the user must refresh the page for updated JS.
- Baseline via app HTTPS, same 190-character Hughgo text, two warm requests before cache: first PCM 3.805 s / 3.501 s, completion 11.457 s / 9.062 s. After cache, six requests: first PCM 2.346, 3.317, 3.560, 3.261, 3.257, 3.244 s; completion varied 6.139–10.778 s. No repeat `[perf] prepared saved voice Hughgo` log after startup. Interpretation: modest first-audio improvement (~0.4 s comparing the warm cluster, noisy sampling), not a solution to most of the ~3 s+ delay. Browser audible playback and overlap/quality remain to check.
- 2026-09-26 latency experiment: pinned upstream `CosyVoice2Model.tts` mutates its shared `self.token_hop_len` from 25 to 50 to 100 during streaming; it never resets it at the next call, so later requests wait for 100 tokens plus lookahead before their first audio. `cosyvoice_ui.py` now resets this to the model's original 25 under its synthesis lock at the start of each synthesis (including Gradio). Baseline, 5 warm direct Hughgo requests: 50-character text median first PCM 3.183 s; 201-character text median 3.248 s. After one restart and initial warm-up, 4 subsequent short requests were 1.605–1.617 s; 5 long requests were 1.613–1.619 s (median 1.615 s). Full completion remains variable (long text 7.972–10.829 s), so this improves first audio, not generation throughput. Three app HTTPS requests returned 100 ms of PCM after 1.862, 1.672 and 1.524 s, each with audio/pcm and several seconds of output. A separate HTTPS PCM integrity check produced 5.84 s of non-silent audio (first-second RMS 0.0576), not a listening/quality check. ASR and TTS health READY; manager tests 240 pass. No audible comparison or full spoken-turn browser timing after change. Qwen first PCM ~0.23 s and 100 ms playable PCM ~1.31 s on its separate earlier deployment; the endpoints and text differ, so this is not an apples-to-apples Qwen benchmark. No profile promotion.
- Playback follow-up: user heard breaks after the 25-token first-hop change. A direct request delivered 1.04 s of initial audio at 1.87 s, but the next chunk did not arrive until 3.42 s, so the app's old 120 ms startup lead could not bridge that gap. Three additional longer streams through app HTTPS needed maximum initial leads of 1.20, 1.31 and 1.32 s to avoid modeled underruns (calculated from chunk arrival time and preceding PCM duration). The app now uses a 1.5 s initial playback lead. Playback may still underrun under different loads.
- Acceleration A/B (Hughgo 201-character text, 4 direct requests, same cached zero-shot voice, 25-token first hop, ASR resident): native FP32 median first PCM 1.629 s and median response completion 10.631 s. Native `fp16=True` after separate restart: warm requests 1.042, 1.048 and 1.047 s to first PCM, median completion across all four requests 7.648 s; first cold request 1.851 s. Idle card memory approximately 9,490 MiB used / 2,633 MiB free with FP16 + ASR, similar to FP32. Synthesized audio is non-silent; the 90-character FP16 sample was transcribed accurately by resident Qwen ASR except that `Hughgo` became `Hugo`. App HTTPS first PCM 1.086 s in one warm test; chunk-timing needed ~0.09 s lead, though the app currently retains the conservative 1.5 s CosyVoice playback lead. This is *not* a listening-based similarity or continuity qualification.
- User listened to Hughgo in the live app and reports that FP16 sounds better and feels more responsive. FP16 is the helper's default; `COSYVOICE_ACCEL=native omm launch rtx4070 cosyvoice3-0.5b-rtx4070` explicitly restores the old FP32 behavior. The committed profile is marked experimental, not fully qualified.
- TensorRT (native CosyVoice `load_trt=True`, FP32 decoder engine, separate candidate image): with ASR running, startup engine build failed on a 3.7 GB GPU allocation and the container restarted; immediately stopped it. With ASR stopped, the ONNX-to-TensorRT engine built and ran. Four Hughgo samples: warm first PCM 1.472–1.475 s, median completion 9.545 s, slower than native FP16 (1.04–1.05 s / 7.648 s). Idle card 9,566 MiB in use **without ASR**, so the native TRT candidate is not co-hostable on this 12 GB card in the current form. ASR was restarted after this test. TRT engine is a machine-local cache artifact under `/model`, not a repo file.
- Native CosyVoice `load_vllm=True` (separate vLLM 0.11.0 + PyTorch 2.8 candidate image, not vLLM-Omni adapter): required `MKL_THREADING_LAYER=GNU` and `VLLM_ENABLE_V1_MULTIPROCESSING=0` to initialize in this prototype; new Pydantic broke pinned Gradio 5.4 API-schema generation, so the candidate served the speech benchmark through a temporary FastAPI-only page without the test UI. ONNX Runtime fell back to CPU for its speech tokenizer because it could not load cuDNN 8 from the upgraded image; this image is not qualified for ongoing use. Four Hughgo samples with ASR stopped: warm first PCM 1.189–1.203 s, median completion 7.776 s, idle GPU 5,146 MiB used. With ASR restarted (READY): four samples warm first PCM 1.195–1.203 s, median completion 7.650 s, GPU 8,606 MiB used. Co-hosting works, but neither first audio nor completion beats FP16. Stopped vLLM, restored FP16 + ASR; validate the user's voice quality again if considering any future vLLM variant.
- A separate FP16 Qwen3-0.6B text annotator briefly co-hosted with both speech services, but a simultaneous speech request caused CosyVoice CUDA out-of-memory and left generation stalled until CosyVoice was restarted. The annotator is stopped and its launch path removed; do not co-host another text model on this card without measuring **speech-time peak** memory, not just idle use.
- FP32 rollback: `omm stop rtx4070 -y` if CosyVoice is running, then `COSYVOICE_ACCEL=native omm launch rtx4070 cosyvoice3-0.5b-rtx4070` and `omm health rtx4070`. Saved voice files are not removed by this switch.
